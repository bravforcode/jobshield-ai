II

The mechanism

Two layers, not one. The first picks the path; the second picks the destination. Wage belongs in the second, not the first.

Layer 1 — path

Dijkstra

cost = α·distnorm + γ·risknorm

Min-cost path from your occupation to every other. Both factors are in [0, 1], so the cost is non-negative and Dijkstra is safe.

The naive formula α·dist − β·wage + γ·risk has two bugs: negative edges break Dijkstra, and the wage term telescopes to (wage(target) − wage(source)) regardless of path. We avoid both.

Layer 2 — target

Rank

score = β·wagenorm − path_cost − γ₂·risk

Once the path is fixed, the destination is chosen by normalising its wage gain across the reachable set and penalising by the path's already-paid cost and the target's AI-displacement risk.

    Wage radar

    Degree centrality (x) vs median wage (y). The fit line is a one-feature ordinary-least-squares regression of wage on centrality. Dots above the line are paid more than their network position predicts; dots below are paid less. The only red on the page is the underpaid signal.

    Appendix

    What this is

    A two-layer recommender. The first layer is a Dijkstra shortest path on a min-max-normalised cost combining skill distance and AI-displacement risk. The second layer is a score that adds a wage term and a target-risk term, but only after the path is fixed. Every recommended path is annotated with the actual shared skills between adjacent occupations.

    What this isn't

    The skill graph is built from data/mock/job_postings.json — a hand-authored proxy, not real Thai labour-market data. Wage numbers are also mock. Spec §8 lists this as limitation #2. We surface it here because the next person who looks at the page should not mistake it for a real index.
